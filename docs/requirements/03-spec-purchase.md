## 1. 공통 사항

### 1.1 발주 상태와 전이

```
          ┌──(승인)──▶ 승인 ──(입고)──▶ 입고완료
  작성 ───┤              │
   │      └──(취소)──▶ 취소 ◀──(취소)──┘
   └─(수정)─┐
      ▲─────┘
```

| 현재 상태 | 가능한 작업 | 작업 후 상태 | 기록 항목 |
|---|---|---|---|
| 작성 | 수정 | 작성 | 수정 일시, 수정자 |
| 작성 | 승인 | 승인 | 승인 일시, 승인자 |
| 작성 | 취소 | 취소 | 취소 일시, 취소 처리자 |
| 승인 | 입고 | 입고완료 | 입고 일시, 입고 처리자 |
| 승인 | 취소 | 취소 | 취소 일시, 취소 처리자 |
| 입고완료 · 취소 | 없음 | - | - |

- 모든 작업은 ADMIN(전 매장) · MANAGER(소속 매장)만 할 수 있다.
- 발주를 등록한 사람이 직접 승인할 수 있다. (BR-057)

### 1.2 동시 처리

- 발주를 수정하거나 상태를 바꿀 때는 **먼저 발주 행을 잠그고(SELECT … FOR UPDATE) 현재 상태를 확인**한다.
  같은 발주에 '입고'와 '취소'가 동시에 요청되어도 먼저 잠근 요청만 처리되고, 나중 요청은 바뀐 상태를 보고 오류가 된다.
- 잠금 순서는 판매와 같이 **업무 문서(발주) → 재고(상품 ID 오름차순)** 로 고정한다.

### 1.3 사용 여부 확인 시점

- 매장 · 공급처 · 상품의 사용 여부는 **발주 등록 · 수정 시에만** 확인한다.
- 이미 등록된 발주는 이후 매장 · 공급처 · 상품이 사용 중지되어도 승인 · 입고 · 취소할 수 있다. (이미 주문한 상품은 받아야 하므로)

## 2. 발주 목록 — SCR-PO-001

**관련 요구사항**: REQ-PO-003 · **사용 역할**: A, M

### 검색 조건

| 항목 | 기본값 | 규칙 |
|---|---|---|
| 발주일 기간 | 오늘 포함 최근 30일 | 시작일 ≤ 종료일, 최대 1년 |
| 상태 | 전체 | 전체 / 작성 / 승인 / 입고완료 / 취소 |
| 공급처 | 전체 | 공급처 목록에서 선택 (사용 중지 공급처 포함) |
| 발주번호 | - | 부분 일치. 입력하면 발주일 기간 조건은 적용하지 않는다. |
| 매장 | 전체 | ADMIN만 표시 |

### 목록

- 항목: 발주번호, 발주일, 매장, 공급처, 품목 수, 합계 금액, 상태
- 발주일은 발주를 등록(작성)한 일시다.
- 정렬: 발주일 내림차순
- 20건 단위 페이지 이동, 총 건수 표시
- 행을 누르면 발주 상세로, '발주 등록' 버튼을 누르면 발주 등록 화면으로 이동한다.
- 기간 오류 메시지는 판매 내역과 같다. ([판매 · 재고 명세 2.2](03-spec-sales-stock.md#22-판매-내역--scr-sale-002))

## 3. 발주 등록 · 수정 — SCR-PO-002

**관련 요구사항**: REQ-PO-001, REQ-PO-002 · **사용 역할**: A, M · **관련 규칙**: BR-014, BR-023, BR-051~054

### 입력 항목

| 항목 | 필수 | 형식 · 범위 | 설명 |
|---|---|---|---|
| 매장 | ADMIN만 필수 | 사용 중인 매장 | MANAGER는 소속 매장 고정. **수정 시에는 변경할 수 없다.** |
| 공급처 | 필수 | 사용 중인 공급처 | |
| 발주 상품 | 필수 | 1 ~ 50개 품목 | 상품 선택 팝업(SCR-PROD-004, 발주 모드)으로 추가 |
| └ 상품 | 필수 | 사용 중인 상품 | 같은 상품은 한 줄에만 담는다. |
| └ 수량 | 필수 | 정수 1 ~ 99,999 | 기본값 1 |
| └ 단가 | 필수 | 정수 0 ~ 99,999,999 | 기본값은 상품 매입가, 수정할 수 있다. |
| └ 금액 | 표시 | - | 단가 × 수량 |
| 합계 금액 | 표시 | - | 발주 상품 금액의 합계 |

### 화면 동작

1. ADMIN은 매장을 먼저 선택해야 상품 선택 버튼이 활성화된다. (팝업의 현재 재고 표시 기준)
2. 이미 담긴 상품을 다시 선택하면 수량을 1 늘린다.
3. 수량 · 단가를 바꾸면 금액과 합계를 바로 다시 계산한다.
4. 수정 화면은 '작성' 상태에서만 열 수 있다. 다른 상태면 `작성 상태의 발주만 수정할 수 있습니다.`를 표시하고 발주 상세로 이동한다.
5. 저장에 성공하면 발주 상세로 이동한다.

### 서버 처리 — 발주 등록

```
[검증]
V1. 매장 결정: MANAGER → 소속 매장 / ADMIN → 요청한 매장
V2. 매장이 사용 중인지 확인
V3. 공급처가 존재하고 사용 중인지 확인
V4. 발주 상품이 1 ~ 50개, 상품 중복 없음, 수량 1 ~ 99,999, 단가 0 ~ 99,999,999인지 확인
V5. 모든 상품이 존재하고 사용 중인지 확인

[트랜잭션 시작]
1. 발주번호를 부여한다
2. 금액 = 단가 × 수량, 합계 금액 = 금액의 합 (서버에서 다시 계산)
3. 발주를 저장한다 (상태 '작성', 발주 일시, 작성자)
4. 발주 상세를 저장한다 (상품, 수량, 단가, 금액)
[트랜잭션 종료]

5. 발주 ID와 발주번호를 반환한다
```

> 판매와 달리 발주 단가는 사용자가 정하는 값이므로 화면에서 보낸 단가를 그대로 사용한다. 금액과 합계만 서버에서 다시 계산한다.

### 서버 처리 — 발주 수정

```
[검증]
V1. 발주가 존재하고, MANAGER는 소속 매장 발주인지 확인
V2. 등록의 V3 ~ V5와 같음

[트랜잭션 시작]
1. 발주 행을 잠그고 상태가 '작성'인지 확인 → 아니면 오류
2. 공급처를 변경하고, 기존 발주 상세를 모두 지운 뒤 새 목록으로 저장한다
3. 합계 금액, 수정 일시, 수정자를 갱신한다
[트랜잭션 종료]
```

### 오류 메시지

| 상황 | 메시지 |
|---|---|
| ADMIN이 매장을 선택하지 않음 | 발주할 매장을 선택하세요. |
| 매장이 사용 중지 상태 | 사용 중지된 매장에서는 발주할 수 없습니다. |
| 공급처 미선택 | 공급처를 선택하세요. |
| 공급처가 없거나 사용 중지 | 발주할 수 없는 공급처입니다. |
| 발주 상품이 없음 | 발주할 상품을 1개 이상 추가하세요. |
| 품목이 50개를 넘음 | 한 번에 최대 50개 상품까지 발주할 수 있습니다. |
| 수량 범위를 벗어남 | 수량은 1 이상 99,999 이하로 입력하세요. |
| 단가 범위를 벗어남 | 단가는 0 이상 99,999,999 이하로 입력하세요. |
| 같은 상품이 중복됨 | 같은 상품이 중복되었습니다. |
| 없거나 사용 중지된 상품 | 발주할 수 없는 상품이 포함되어 있습니다: {상품명} |
| '작성'이 아닌 발주를 수정 | 작성 상태의 발주만 수정할 수 있습니다. |

## 4. 발주 상세 · 승인 · 입고 · 취소 — SCR-PO-003

**관련 요구사항**: REQ-PO-004~007 · **사용 역할**: A, M · **관련 규칙**: BR-036, BR-050, BR-055~057

### 표시 항목

| 영역 | 항목 |
|---|---|
| 발주 정보 | 발주번호, 매장, 공급처, 상태, 합계 금액 |
| 발주 상품 | 상품코드, 상품명, 수량, 단가, 금액 |
| 처리 이력 | 작성 · 승인 · 입고 · 취소 각각의 일시와 처리자 (처리된 단계만 표시) |

- 없는 발주면 페이지 없음, MANAGER가 다른 매장 발주에 접근하면 권한 없음 화면을 보여준다.

### 상태별 버튼

| 상태 | 버튼 |
|---|---|
| 작성 | 수정, 승인, 취소 |
| 승인 | 입고, 취소 |
| 입고완료 · 취소 | 없음 |

### 확인 대화상자

| 작업 | 메시지 |
|---|---|
| 승인 | 발주를 승인하시겠습니까? 승인 후에는 내용을 수정할 수 없습니다. |
| 입고 | 발주 수량 전량을 입고 처리하시겠습니까? 매장 재고가 증가합니다. |
| 취소 | 발주 {발주번호}를 취소하시겠습니까? |

### 서버 처리 — 승인 · 취소

```
[검증]
V1. 발주가 존재하고, MANAGER는 소속 매장 발주인지 확인

[트랜잭션 시작]
1. 발주 행을 잠그고 현재 상태를 확인한다
   - 승인: '작성'이 아니면 오류
   - 취소: '작성' · '승인'이 아니면 오류
2. 상태를 변경하고 해당 작업의 일시 · 처리자를 기록한다
[트랜잭션 종료]
```

- 취소는 재고를 바꾸지 않는다. (입고 전에만 취소할 수 있으므로)

### 서버 처리 — 입고 ★

```
[검증]
V1. 발주가 존재하고, MANAGER는 소속 매장 발주인지 확인

[트랜잭션 시작]
1. 발주 행을 잠그고 상태가 '승인'인지 확인 → 아니면 오류
2. 상태를 '입고완료'로 변경하고 입고 일시 · 입고 처리자를 기록한다
3. 재고 변경 공통 절차 실행 (판매 · 재고 명세 1.3)
   - 발주 상세의 상품마다 유형 '입고', 변동 수량 = +발주 수량, 관련 문서 = 이 발주
   - 발주 매장의 재고가 증가한다 (BR-051)
[트랜잭션 종료]
```

- 발주 수량 전량을 한 번에 입고한다. (부분 입고 없음, BR-055)
- 입고해도 상품의 매입가는 바뀌지 않는다. 발주 단가는 발주 상세에만 남는다.

### 오류 메시지

| 상황 | 메시지 |
|---|---|
| 없는 발주 | 존재하지 않는 발주입니다. |
| USER 요청 · 다른 매장 발주 | 발주를 처리할 권한이 없습니다. |
| '작성'이 아닌 발주를 승인 | 작성 상태의 발주만 승인할 수 있습니다. |
| '승인'이 아닌 발주를 입고 | 승인된 발주만 입고 처리할 수 있습니다. |
| '입고완료' · '취소' 발주를 취소 | 입고 전의 발주만 취소할 수 있습니다. |

## 6. 확정 시 결정 사항

| # | 항목 | 결정 | 채택하지 않은 안 |
|---|---|---|---|
| 1 | 발주 한도 | 최대 50개 품목, 품목당 수량 99,999, 단가 0 ~ 99,999,999 | 다른 값 |
| 2 | 발주 목록 기본 조회 기간 | 최근 30일 (판매보다 발생 빈도가 낮음) | 판매와 같이 최근 7일 |
| 3 | 사용 여부 확인 시점 (1.3) | 등록 · 수정 시에만 확인, 승인 · 입고는 허용 | 승인 · 입고 시에도 확인해서 막음 |
| 4 | 입고 시 상품 매입가 갱신 | 갱신하지 않음 | 마지막 입고 단가로 매입가 갱신 |
