## 1. 공통 사항

### 1.1 상태와 유형

| 구분 | 값 | 설명 |
|---|---|---|
| 판매 상태 | 완료 | 판매 등록이 끝난 상태 |
| | 취소 | 판매 취소가 끝난 상태 |
| 재고 변동 유형 | 판매 | 판매로 재고 감소 (−) |
| | 판매 취소 | 판매 취소로 재고 복원 (+) |
| | 입고 | 발주 입고로 재고 증가 (+) — 발주 명세에서 사용 |
| | 조정 | 재고 조정으로 증가 또는 감소 (±) |

### 1.2 데이터 범위 처리

| 역할 | 목록 · 조회 | 등록 | 다른 매장 데이터 상세 접근 |
|---|---|---|---|
| ADMIN | 매장 조건 선택 (미선택 시 전체) | 매장 선택 필수 (사용 중인 매장만 선택 가능) | 가능 |
| MANAGER · USER | 소속 매장으로 고정 (요청의 매장 값은 무시) | 소속 매장으로 고정 | 권한 없음 (SCR-COM-002) |

### 1.3 재고 변경 공통 절차 ★

BR-031에 따라 재고는 **판매 · 판매 취소 · 입고 · 조정**으로만 바뀌며, 네 업무 모두 아래 절차 하나만 사용한다.
이 절차는 **호출한 업무의 트랜잭션 안에서** 실행되며, 실패하면 호출한 업무 전체가 롤백된다.

```
입력: 매장, [상품, 변동 수량(+/−)] 목록, 변동 유형, 관련 문서(판매 · 발주, 없으면 생략), 사유(조정 시), 처리자

1. 대상 재고 행을 상품 ID 오름차순으로 잠근다 (SELECT … FOR UPDATE)
2. 상품마다:
   2-1. 변동 전 수량을 읽는다
   2-2. 변동 후 수량 = 변동 전 수량 + 변동 수량
   2-3. 변동 후 수량 < 0 이면 → 오류 (재고 부족), 전체 롤백
   2-4. 재고 수량을 변동 후 수량으로 변경한다
   2-5. 재고 이력 1건을 기록한다
        (유형, 변동 수량, 변동 전 · 후 수량, 관련 문서, 사유, 처리자, 처리 일시)
```

### 1.4 동시성 처리 (NFR-004)

| 상황 | 처리 방식 |
|---|---|
| 남은 재고 1개를 두 판매가 동시에 요청 | 재고 행을 잠근(1.3의 1단계) 요청이 먼저 처리된다. 나중 요청은 잠금이 풀린 뒤 **최신 수량**을 읽으므로 재고 부족으로 실패한다. |
| 여러 상품을 담은 판매 두 건이 서로 다른 순서로 재고를 잠금 | 항상 **상품 ID 오름차순**으로 잠가서 서로 상대의 잠금을 기다리는 교착 상태(deadlock)를 막는다. |
| 같은 판매에 취소 요청이 동시에 두 번 들어옴 | 판매 상태를 **'완료'인 경우에만 '취소'로 바꾸는 조건부 변경**을 먼저 실행한다. 변경된 행이 없으면 이미 취소된 판매로 보고 오류를 반환하므로 재고가 두 번 복원되지 않는다. |

### 1.5 재고 행 생성 시점

- 매장이나 상품이 등록되면 **모든 매장 × 상품 조합의 재고 행을 수량 0, 안전재고 0으로 미리 생성**한다.
  (매장 등록 · 상품 등록 명세에서 해당 처리를 포함한다)
- 따라서 판매 · 조정 시 재고 행은 항상 존재하며, 1.3의 잠금 대상이 없는 경우가 생기지 않는다.

### 1.6 기타

- 처리자는 로그인한 사용자, 처리 일시는 서버의 현재 시각(Asia/Seoul)이다.
- 목록 화면의 검색 조건은 URL 쿼리에 유지한다. (뒤로 가기, Dashboard 링크에서 조건 유지)
- 버튼을 누른 뒤 서버 처리가 끝날 때까지 버튼을 비활성화하여 중복 요청을 막는다.

## 2. 판매

### 2.1 판매 등록 — SCR-SALE-001

**관련 요구사항**: REQ-SALE-001 · **사용 역할**: A, M, U · **관련 규칙**: BR-014, BR-023, BR-036, BR-040~043

#### 입력 항목

| 항목 | 필수 | 형식 · 범위 | 설명 |
|---|---|---|---|
| 매장 | ADMIN만 필수 | 사용 중인 매장 | MANAGER · USER는 소속 매장이 표시되고 변경할 수 없다. |
| 판매 상품 | 필수 | 1 ~ 50개 품목 | 상품 선택 팝업(SCR-PROD-004)으로 추가한다. |
| └ 상품 | 필수 | 사용 중인 상품 | 같은 상품은 한 줄에만 담는다. |
| └ 수량 | 필수 | 정수 1 ~ 9,999 | 기본값 1 |
| └ 단가 | 표시 | - | 상품의 현재 판매가. 수정할 수 없다. |
| └ 금액 | 표시 | - | 단가 × 수량 |
| └ 현재 재고 | 표시 | - | 상품을 담은 시점의 재고 (참고용) |
| 합계 금액 | 표시 | - | 판매 상품 금액의 합계 |

#### 화면 동작

1. ADMIN은 매장을 먼저 선택해야 상품 선택 버튼이 활성화된다. 매장을 바꾸면 담은 상품이 초기화된다.
2. 상품 선택 팝업에서 이미 담긴 상품을 다시 선택하면 새 줄을 만들지 않고 **수량을 1 늘린다**.
3. 수량을 바꾸면 금액과 합계를 바로 다시 계산한다.
4. 수량이 표시된 현재 재고보다 많으면 해당 줄에 경고를 표시하고 판매 완료 버튼을 비활성화한다. (최종 판단은 서버가 한다)
5. 판매 완료 버튼 → 확인 대화상자: `합계 {합계 금액}원을 판매 완료하시겠습니까?`
6. 성공하면 판매 상세(SCR-SALE-003)로 이동한다.

#### 서버 처리

```
[검증]
V1. 매장 결정: MANAGER · USER → 소속 매장 / ADMIN → 요청한 매장
V2. 매장이 사용 중인지 확인
V3. 판매 상품이 1 ~ 50개이고, 같은 상품이 중복되지 않았고, 수량이 1 ~ 9,999인지 확인
V4. 모든 상품이 존재하고 사용 중인지 확인

[트랜잭션 시작]
1. 판매번호를 부여한다
2. 상품마다 단가 = 현재 판매가 (서버에서 조회하며, 화면에서 보낸 값은 사용하지 않음)
3. 금액 = 단가 × 수량, 합계 금액 = 금액의 합
4. 판매를 저장한다 (상태 '완료', 판매 일시, 처리자)
5. 판매 상세를 저장한다 (상품, 수량, 단가, 금액)
6. 재고 변경 공통 절차 (1.3) 실행
   - 유형 '판매', 변동 수량 = −수량, 관련 문서 = 이 판매
   - 하나라도 재고가 부족하면 오류 → 1~5 포함 전체 롤백
[트랜잭션 종료]

7. 판매 ID와 판매번호를 반환한다
```

#### 오류 메시지

| 상황 | 메시지 |
|---|---|
| ADMIN이 매장을 선택하지 않음 | 판매할 매장을 선택하세요. |
| 매장이 사용 중지 상태 | 사용 중지된 매장에서는 판매할 수 없습니다. |
| 판매 상품이 없음 | 판매할 상품을 1개 이상 추가하세요. |
| 품목이 50개를 넘음 | 한 번에 최대 50개 상품까지 판매할 수 있습니다. |
| 수량 범위를 벗어남 | 수량은 1 이상 9,999 이하로 입력하세요. |
| 같은 상품이 중복됨 | 같은 상품이 중복되었습니다. |
| 없거나 사용 중지된 상품 | 판매할 수 없는 상품이 포함되어 있습니다: {상품명} |
| 재고 부족 | 재고가 부족합니다: {상품명} (현재 재고 {현재 수량}개, 판매 수량 {판매 수량}개) |

### 2.2 판매 내역 — SCR-SALE-002

**관련 요구사항**: REQ-SALE-002 · **사용 역할**: A, M, U

#### 검색 조건

| 항목 | 기본값 | 규칙 |
|---|---|---|
| 판매일 기간 | 오늘 포함 최근 7일 | 시작일 ≤ 종료일, 최대 1년 |
| 판매번호 | - | 부분 일치. 입력하면 판매일 기간 조건은 적용하지 않는다. |
| 상태 | 전체 | 전체 / 완료 / 취소 |
| 매장 | 전체 | ADMIN만 표시 |

#### 목록

- 항목: 판매번호, 판매 일시, 매장, 품목 수, 합계 금액, 상태, 처리자
- 정렬: 판매 일시 내림차순
- 20건 단위 페이지 이동, 총 건수 표시
- '취소' 상태는 구분되는 색으로 표시한다.
- 행을 누르면 판매 상세로 이동한다.

#### 오류 메시지

| 상황 | 메시지 |
|---|---|
| 시작일이 종료일보다 늦음 | 시작일은 종료일보다 늦을 수 없습니다. |
| 기간이 1년을 넘음 | 조회 기간은 최대 1년입니다. |

### 2.3 판매 상세 · 판매 취소 — SCR-SALE-003

**관련 요구사항**: REQ-SALE-003, REQ-SALE-004 · **사용 역할**: 조회 A, M, U / 취소 A, M · **관련 규칙**: BR-036, BR-045, BR-046

#### 표시 항목

| 영역 | 항목 |
|---|---|
| 판매 정보 | 판매번호, 매장, 판매 일시, 상태, 처리자, 취소 일시 · 취소 처리자('취소' 상태일 때) |
| 판매 상품 | 상품코드, 상품명, 단가, 수량, 금액 |
| 합계 | 합계 금액 |

- 없는 판매면 페이지 없음, 다른 매장 판매에 MANAGER · USER가 접근하면 권한 없음 화면(SCR-COM-002)을 보여준다.

#### 판매 취소

- 버튼 표시 조건: ADMIN · MANAGER이고 상태가 '완료'일 때
- 확인 대화상자: `판매번호 {판매번호}를 취소하시겠습니까? 판매 수량만큼 재고가 복원됩니다.`
- 매장이나 상품이 사용 중지 상태여도 취소할 수 있다. 취소 가능 기간 제한은 없다.

#### 서버 처리 (판매 취소)

```
[검증]
V1. 판매가 존재하는지 확인
V2. 역할이 ADMIN · MANAGER인지 확인
V3. MANAGER는 소속 매장의 판매인지 확인

[트랜잭션 시작]
1. 판매 상태를 '완료'인 경우에만 '취소'로 변경한다 (조건부 변경)
   - 변경된 행이 없으면 → 오류 (이미 취소된 판매)
   - 취소 일시, 취소 처리자를 기록한다
2. 재고 변경 공통 절차 (1.3) 실행
   - 판매 상세의 상품마다 유형 '판매 취소', 변동 수량 = +판매 수량, 관련 문서 = 이 판매
[트랜잭션 종료]

3. 화면은 판매 상세를 다시 조회해 '취소' 상태를 표시한다
```

#### 오류 메시지

| 상황 | 메시지 |
|---|---|
| 없는 판매 | 존재하지 않는 판매입니다. |
| USER가 취소 요청 · 다른 매장 판매 | 판매를 취소할 권한이 없습니다. |
| 이미 취소된 판매 | 이미 취소된 판매입니다. |

## 3. 재고

### 3.1 현재 재고 — SCR-STOCK-001

**관련 요구사항**: REQ-STOCK-001, REQ-STOCK-006 · **사용 역할**: A, M, U · **관련 규칙**: BR-030, BR-035

#### 검색 조건

| 항목 | 기본값 | 규칙 |
|---|---|---|
| 상품 | - | 상품명 · 상품코드 부분 일치 |
| 카테고리 | 전체 | |
| 부족 재고만 보기 | 해제 | 체크하면 부족 재고만 표시 |
| 매장 | 전체 | ADMIN만 표시 |

#### 목록

- 항목: 매장, 상품코드, 상품명, 카테고리, 현재 수량, 안전재고, 부족 여부
- **부족 재고 판단**: 사용 중인 상품이고 `현재 수량 < 안전재고`인 경우. 안전재고가 0이면 부족으로 보지 않는다.
- 사용 중지된 상품도 목록에 표시하되 상품명 옆에 '사용 중지'를 표시하고, 부족 재고 판단에서는 제외한다.
- 정렬: 매장명, 상품코드 오름차순
- 행을 누르면 재고 상세로 이동한다. (ADMIN은 매장 ID를 함께 전달)
- Dashboard의 재고 부족 상품에서 이동하면 '부족 재고만 보기'가 체크된 상태로 열린다.

### 3.2 재고 상세 — SCR-STOCK-002

**관련 요구사항**: REQ-STOCK-002 · **사용 역할**: 조회 A, M, U / 조정 · 안전재고 설정 A, M

#### 표시 항목

| 영역 | 항목 |
|---|---|
| 재고 정보 | 매장, 상품코드, 상품명, 카테고리, 상품 상태, 현재 수량, 안전재고, 부족 여부 |
| 최근 변동 이력 | 최근 10건 (일시, 변동 유형, 변동 수량, 변동 전 → 후, 관련 번호, 사유, 처리자) |

- '전체 이력 보기'를 누르면 이 매장 · 상품 조건으로 재고 이력(SCR-STOCK-005)을 연다.
- 재고 조정 · 안전재고 설정 버튼은 ADMIN · MANAGER에게만 표시한다.
- ADMIN이 매장 지정 없이 접근하면 현재 재고 화면으로 이동한다.

### 3.3 재고 조정 — SCR-STOCK-003 (팝업)

**관련 요구사항**: REQ-STOCK-004 · **사용 역할**: A, M · **관련 규칙**: BR-031~034, BR-036

#### 입력 항목

| 항목 | 필수 | 형식 · 범위 | 설명 |
|---|---|---|---|
| 현재 수량 | 표시 | - | 팝업을 연 시점의 수량 |
| 조정 구분 | 필수 | 증가 / 감소 | |
| 조정 수량 | 필수 | 정수 1 ~ 9,999 | |
| 조정 후 수량 | 표시 | - | 현재 수량 ± 조정 수량 (미리보기) |
| 조정 사유 | 필수 | 1 ~ 200자 | 공백만 입력할 수 없다. |

- 조정 후 수량 미리보기가 0보다 작으면 경고를 표시하고 저장 버튼을 비활성화한다.
- 사용 중지된 상품도 조정할 수 있다. (남은 재고 정리용)

#### 서버 처리

```
[검증]
V1. 역할이 ADMIN · MANAGER인지, MANAGER는 소속 매장인지 확인
V2. 조정 수량 1 ~ 9,999, 조정 사유 1 ~ 200자 (앞뒤 공백 제거 후) 확인

[트랜잭션 시작]
1. 재고 변경 공통 절차 (1.3) 실행
   - 유형 '조정', 변동 수량 = 증가면 +수량, 감소면 −수량, 사유 = 조정 사유, 관련 문서 없음
   - 변동 후 수량 < 0 이면 오류 → 롤백
[트랜잭션 종료]

2. 변동 후 수량을 반환한다
   (팝업을 연 뒤 다른 판매가 먼저 처리됐다면 미리보기와 결과가 다를 수 있으므로, 완료 메시지에 실제 결과를 표시한다)
```

#### 오류 · 완료 메시지

| 상황 | 메시지 |
|---|---|
| 조정 사유 없음 | 조정 사유를 입력하세요. |
| 조정 사유가 200자를 넘음 | 조정 사유는 200자 이하로 입력하세요. |
| 조정 수량 범위를 벗어남 | 조정 수량은 1 이상 9,999 이하로 입력하세요. |
| 조정 후 수량이 0보다 작음 | 조정 후 재고는 0보다 작을 수 없습니다. (현재 재고 {현재 수량}개) |
| 완료 | 재고가 조정되었습니다. ({변동 전 수량}개 → {변동 후 수량}개) |

### 3.5 재고 이력 — SCR-STOCK-005

**관련 요구사항**: REQ-STOCK-003 · **사용 역할**: A, M, U · **관련 규칙**: BR-032

#### 검색 조건

|---|---|---|
| 기간 | 오늘 포함 최근 7일 | 시작일 ≤ 종료일, 최대 1년 |
| 상품 | - | 상품명 · 상품코드 부분 일치 |
| 변동 유형 | 전체 | 전체 / 판매 / 판매 취소 / 입고 / 조정 |
| 매장 | 전체 | ADMIN만 표시 |

#### 목록

- 항목: 일시, 매장, 상품코드, 상품명, 변동 유형, 변동 수량, 변동 전 수량, 변동 후 수량, 관련 번호, 사유, 처리자
- 변동 수량은 `+5`, `−3`처럼 부호를 붙이고 증가 · 감소를 다른 색으로 표시한다.
- 정렬: 일시 내림차순 (같은 일시면 나중에 기록된 순)
- 관련 번호: 판매번호 → 판매 상세, 발주번호 → 발주 상세로 이동한다. USER에게는 발주번호를 링크 없이 표시한다.
- **재고 이력은 수정 · 삭제할 수 없다.**
- 기간 오류 메시지는 판매 내역(2.2)과 같다.
