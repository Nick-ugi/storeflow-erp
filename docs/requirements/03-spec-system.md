## 1. 인증

### 1.1 인증 방식

| 항목 | 내용 |
|---|---|
| 토큰 | JWT Access Token 1개 (Refresh Token 없음) |
| 유효 기간 | **8시간** (근무 1일 기준). 만료되면 다시 로그인한다. |
| 전달 방식 | 요청 헤더 `Authorization: Bearer {토큰}` (NFR-001) |
| 토큰에 담는 정보 | 사용자 식별값만. 역할 · 소속 매장은 담지 않는다. |
| 요청마다 확인 | 서버는 요청마다 사용자를 조회해 **활성 상태, 현재 역할, 현재 소속 매장**을 확인한다. |

- 요청마다 확인하므로 ADMIN이 사용자를 **비활성화하거나 역할 · 소속 매장을 바꾸면 다음 요청부터 바로 반영**된다.
  (토큰에 역할을 담으면 만료될 때까지 이전 권한이 유지되는 문제가 있다)

### 1.2 로그인 — SCR-AUTH-001

**관련 요구사항**: REQ-AUTH-001 · **관련 규칙**: BR-012, BR-013

| 항목 | 필수 | 설명 |
|---|---|---|
| 아이디 | 필수 | |
| 비밀번호 | 필수 | 입력 내용을 가려서 표시 |

```
[서버 처리]
1. 아이디로 사용자를 조회한다
2. 비밀번호를 BCrypt로 비교한다
3. 사용자가 없거나 비밀번호가 틀리면 → 같은 메시지로 실패 처리 (어느 쪽이 틀렸는지 알려주지 않음)
4. 비밀번호가 맞아도 비활성 사용자면 → 실패
5. 토큰을 발급하고 사용자 정보(이름, 역할, 소속 매장)를 함께 반환한다
```

- 로그인에 성공하면 Dashboard로 이동한다. 로그인 만료로 로그인 화면에 온 경우에는 **원래 보던 화면으로 돌아간다.**
- 사용 중지된 매장의 사용자도 로그인할 수 있다. (조회는 가능하고, 새 판매 · 발주 등록만 막힘 — BR-014)
- 로그인 실패 횟수 제한(계정 잠금)은 이번 범위에 포함하지 않는다.

| 상황 | 메시지 |
|---|---|
| 아이디 · 비밀번호 미입력 | 아이디와 비밀번호를 입력하세요. |
| 아이디 없음 · 비밀번호 불일치 | 아이디 또는 비밀번호가 올바르지 않습니다. |
| 비활성 사용자 | 사용이 중지된 계정입니다. 관리자에게 문의하세요. |

### 1.3 로그아웃 · 내 정보 — SCR-COM-001

**관련 요구사항**: REQ-AUTH-002, REQ-AUTH-003

- **로그아웃**: 브라우저에 보관한 토큰을 삭제하고 로그인 화면으로 이동한다. 서버는 별도 처리를 하지 않는다.
- **내 정보**: 헤더에 이름, 역할, 소속 매장명(ADMIN은 '본사')을 표시한다. 로그인 직후와 새로고침 시 서버에서 다시 조회한다.

### 1.4 비밀번호 변경 — SCR-AUTH-002 (팝업, 선택 기능)

**관련 요구사항**: REQ-AUTH-004 · **사용 역할**: A, M, U

| 항목 | 필수 | 규칙 |
|---|---|---|
| 현재 비밀번호 | 필수 | 저장된 비밀번호와 일치해야 한다. |
| 새 비밀번호 | 필수 | 비밀번호 규칙(1.5)을 따르고, 현재 비밀번호와 달라야 한다. |
| 새 비밀번호 확인 | 필수 | 새 비밀번호와 같아야 한다. |

| 상황 | 메시지 |
|---|---|
| 현재 비밀번호 불일치 | 현재 비밀번호가 올바르지 않습니다. |
| 규칙 위반 | 비밀번호는 영문과 숫자를 포함해 8~20자로 입력하세요. |
| 현재 비밀번호와 같음 | 현재 비밀번호와 다른 비밀번호를 입력하세요. |
| 확인 불일치 | 새 비밀번호가 일치하지 않습니다. |

### 1.5 비밀번호 규칙

- 8 ~ 20자, **영문과 숫자를 각각 1자 이상** 포함한다.
- 사용자 등록의 초기 비밀번호, 비밀번호 초기화, 비밀번호 변경에 모두 적용한다.
- BCrypt로 암호화하여 저장하고, 어떤 응답에도 포함하지 않는다. (NFR-002)

**관련 요구사항**: REQ-STORE-001 · **사용 역할**: A

| 검색 항목 | 기본값 | 규칙 |

### 3.2 매장 등록 · 수정 · 사용 중지 — SCR-STORE-002 (팝업)

**관련 요구사항**: REQ-STORE-002~005 · **사용 역할**: A · **관련 규칙**: BR-010, BR-014

| 항목 | 필수 | 형식 · 범위 | 설명 |
|---|---|---|---|
| 매장코드 | 필수 | 영문 대문자 · 숫자, 2 ~ 10자 | 중복 불가. **등록 시에만 입력**, 수정할 수 없다. (판매번호 · 발주번호에 사용될 수 있음 — ⑦에서 확정) |

| 주소 | 선택 | 0 ~ 200자 | |
| 전화번호 | 선택 | 숫자 · 하이픈, 최대 20자 | |

```
[서버 처리 — 매장 등록]
1. 역할이 ADMIN인지, 입력 형식 · 중복을 확인한다
[트랜잭션 시작]
2. 매장 · 상품 등록 공통 잠금을 획득한다 (기준정보 명세 4장)
3. 매장을 저장한다 (상태 '사용')
4. 모든 상품(사용 중지 상품 포함)에 대해 이 매장의 재고 행을 생성한다 (수량 0, 안전재고 0)
[트랜잭션 종료]
```

- 수정 팝업에는 사용 중지 / 다시 사용 버튼을 표시한다.

| 작업 | 확인 대화상자 |

| 사용 중지 | 매장을 사용 중지하시겠습니까? 이 매장에서 새 판매 · 발주를 등록할 수 없게 됩니다. |
| 다시 사용 | 매장을 다시 사용하시겠습니까? |

| 상황 | 메시지 |
|---|---|
| 필수 항목 누락 | {항목명}을(를) 입력하세요. |
| 매장코드 형식 오류 | 매장코드는 영문 대문자와 숫자로 2~10자로 입력하세요. |
| 매장코드 중복 | 이미 사용 중인 매장코드입니다. |
| 매장명 중복 | 이미 사용 중인 매장명입니다. |

## 4. 사용자 관리

### 4.1 사용자 목록 — SCR-USER-001

**관련 요구사항**: REQ-USER-001 · **사용 역할**: A

| 검색 항목 | 기본값 | 규칙 |
|---|---|---|
| 사용자 | - | 이름 · 아이디 부분 일치 |
| 역할 | 전체 | 전체 / ADMIN / MANAGER / USER |
| 소속 매장 | 전체 | |
| 상태 | 전체 | 전체 / 활성 / 비활성 |

- 항목: 아이디, 이름, 역할, 소속 매장, 상태, 등록일
- 정렬: 아이디 오름차순, 20건 단위 페이지 이동

### 4.2 사용자 등록 · 수정 · 비활성화 — SCR-USER-002 (팝업)

**관련 요구사항**: REQ-USER-002~005 · **사용 역할**: A · **관련 규칙**: BR-011~013

| 항목 | 필수 | 형식 · 범위 | 설명 |
|---|---|---|---|
| 아이디 | 필수 | 영문 소문자 · 숫자, 4 ~ 20자 | 중복 불가. **등록 시에만 입력** |
| 초기 비밀번호 | 필수 | 비밀번호 규칙 (1.5) | **등록 시에만 입력**. 수정 팝업에서는 비밀번호를 다루지 않는다. |
| 이름 | 필수 | 1 ~ 50자 | |
| 역할 | 필수 | ADMIN / MANAGER / USER | |
| 소속 매장 | 조건부 | 사용 중인 매장 | MANAGER · USER는 필수, ADMIN은 선택할 수 없다. |

#### 규칙

1. 역할을 ADMIN으로 바꾸면 소속 매장이 비워진다. MANAGER · USER로 바꾸면 소속 매장을 선택해야 한다.
2. **ADMIN은 자기 계정을 비활성화하거나 자기 역할을 바꿀 수 없다.** (스스로 관리 권한을 잃는 것을 방지)
3. **활성 ADMIN이 1명뿐이면 그 계정은 비활성화하거나 다른 역할로 바꿀 수 없다.**
4. 수정 팝업에는 비활성화 / 다시 활성화, 비밀번호 초기화 버튼을 표시한다.
5. 역할 · 소속 매장 변경과 비활성화는 해당 사용자의 다음 요청부터 바로 적용된다. (1.1)

| 작업 | 확인 대화상자 |
|---|---|
| 비활성화 | 사용자를 비활성화하시겠습니까? 이 사용자는 더 이상 로그인할 수 없습니다. |
| 다시 활성화 | 사용자를 다시 활성화하시겠습니까? |

| 상황 | 메시지 |
|---|---|
| 필수 항목 누락 | {항목명}을(를) 입력하세요. |
| 아이디 형식 오류 | 아이디는 영문 소문자와 숫자로 4~20자로 입력하세요. |
| 아이디 중복 | 이미 사용 중인 아이디입니다. |
| 비밀번호 규칙 위반 | 비밀번호는 영문과 숫자를 포함해 8~20자로 입력하세요. |
| 소속 매장 누락 | MANAGER와 USER는 소속 매장을 선택해야 합니다. |
| 본인 계정 변경 | 본인 계정의 역할과 상태는 변경할 수 없습니다. |
| 마지막 ADMIN | 활성 ADMIN이 최소 1명 있어야 합니다. |

### 4.3 비밀번호 초기화 — SCR-USER-003 (팝업, 선택 기능)

**관련 요구사항**: REQ-USER-006 · **사용 역할**: A

| 항목 | 필수 | 규칙 |
|---|---|---|
| 새 초기 비밀번호 | 필수 | 비밀번호 규칙 (1.5) |
| 새 초기 비밀번호 확인 | 필수 | 위와 같아야 한다. |

- 다음 로그인 시 비밀번호 변경을 강제하는 기능은 이번 범위에 포함하지 않는다.

### 4.4 초기 ADMIN 계정

- 사용자는 ADMIN만 만들 수 있으므로, **시스템 최초 실행 시 ADMIN 계정 1개를 초기 데이터로 생성**한다. (Flyway 마이그레이션)
- 초기 아이디 · 비밀번호는 구현 단계에서 정하고 README에 기재한다. 첫 로그인 후 비밀번호 변경을 권장한다.

## 5. Dashboard — SCR-DASH-001

**관련 요구사항**: REQ-DASH-001~007 · **사용 역할**: A, M, U · **관련 규칙**: BR-006, BR-060, BR-061

### 5.1 집계 기준

| 구분 | 기준 |
|---|---|
| 데이터 범위 | MANAGER · USER: 소속 매장 / ADMIN: 전 매장 합계 (매장 선택 시 해당 매장) |
| 매출 | '완료' 상태 판매의 합계 금액. 취소된 판매는 판매일 매출에서 빠진다. |
| 날짜 | 한국 시간(Asia/Seoul) 기준. '오늘'은 00:00부터 현재까지 |

### 5.2 표시 항목

| 영역 | 요구사항 | 내용 |
|---|---|---|
| 오늘 매출 | REQ-DASH-001 | 오늘 매출 금액, 판매 건수 |
| 이번 달 매출 | REQ-DASH-002 | 이번 달 1일부터 오늘까지 매출 금액, 판매 건수 |
| 매출 추이 | REQ-DASH-003 | 오늘 포함 최근 7일의 일별 매출 그래프. 판매가 없는 날은 0으로 표시 |
| 재고 현황 | REQ-DASH-004 | 재고 보유 상품 수(현재 수량 1 이상), 부족 재고 상품 수 |
| 재고 부족 상품 | REQ-DASH-005 | 부족 수량(안전재고 − 현재 수량)이 큰 순서로 5건. ADMIN 전체 기준이면 매장도 표시. '전체 보기' → 현재 재고(부족 재고만 보기) |
| 최근 판매 | REQ-DASH-006 | 판매 일시 최근 순 5건 (판매번호, 일시, 합계 금액, 상태). 누르면 판매 상세 |
| 최근 발주 | REQ-DASH-007 | 발주 일시 최근 순 5건 (발주번호, 공급처, 상태). ADMIN · MANAGER만 표시. 누르면 발주 상세 |

- ADMIN 전체 기준의 **재고 보유 상품 수**는 전 매장 합계 수량이 1 이상인 상품 수, **부족 재고 상품 수**는 부족 상태인 매장 × 상품 건수다.
- 화면에 들어올 때 조회하며, '새로고침' 버튼으로 다시 조회한다. 자동 갱신은 하지 않는다.

| 데이터 | 항목 |

| 매장 | 매장코드(중복 불가), 매장명(중복 불가), 주소, 전화번호, 사용 여부, 생성 · 수정 일시 |
| 사용자 | 아이디(중복 불가), 비밀번호(암호화), 이름, 역할, 소속 매장(ADMIN은 없음), 상태, 생성 · 수정 일시 |

- 역할은 3개로 고정되어 있으므로, 별도 역할 테이블로 둘지 사용자의 코드 값으로 둘지는 ④에서 정한다.
