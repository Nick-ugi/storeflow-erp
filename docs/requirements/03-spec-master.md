## 1. 공통 사항

### 1.1 권한

- 조회는 ADMIN · MANAGER · USER 모두 가능하다.
- 등록 · 수정 · 사용 중지는 **ADMIN만** 가능하다. (BR-021) 다른 역할의 요청은 권한 없음으로 거부한다.

### 1.2 사용 여부

- 상품 · 공급처는 '사용' / '사용 중지' 상태를 가진다. 삭제 기능은 없다. (BR-004)
- **사용 중지된 데이터는 다시 '사용'으로 되돌릴 수 있다.** (잘못 중지한 경우, 판매를 재개하는 경우)
- 카테고리는 사용 여부 없이 등록 · 수정만 한다. (BR-004)

### 1.3 입력값 공통 처리

- 문자 입력값은 앞뒤 공백을 제거한 뒤 검증 · 저장한다.
- 중복 검사(상품코드, 카테고리명, 사업자등록번호)는 DB의 중복 불가 제약으로도 보장한다.
  두 요청이 동시에 같은 값을 등록하면 하나는 제약 위반이 되며, 이때도 중복 오류 메시지를 보여준다.

## 2. 카테고리

### 2.1 카테고리 목록 — SCR-CAT-001

**관련 요구사항**: REQ-CAT-001 · **사용 역할**: A, M, U

- 항목: 카테고리명, 설명
- 정렬: 카테고리명 오름차순

- 카테고리 목록은 상품 목록 · 상품 등록 · 현재 재고 화면의 카테고리 선택 목록에도 사용된다.

| 카테고리명 | 필수 | 1 ~ 50자 | 중복 불가 |
| 설명 | 선택 | 0 ~ 200자 | |

| 상황 | 메시지 |
|---|---|

| 길이 초과 | 카테고리명은 50자, 설명은 200자 이하로 입력하세요. |

## 3. 상품

### 3.1 상품 목록 — SCR-PROD-001

**관련 요구사항**: REQ-PROD-001 · **사용 역할**: A, M, U

#### 검색 조건

| 항목 | 기본값 | 규칙 |
|---|---|---|
| 상품 | - | 상품명 · 상품코드 부분 일치 |
| 카테고리 | 전체 | |
| 상태 | 사용 | 전체 / 사용 / 사용 중지 |
| 매장 | 전체 | ADMIN만 표시. 재고 수량 표시 기준 |

#### 목록

- 항목: 상품코드, 상품명, 카테고리, 판매가, 재고, 상태
- **재고**: MANAGER · USER는 소속 매장 수량, ADMIN은 선택한 매장 수량 (매장 미선택 시 전 매장 합계)
- 정렬: 상품코드 오름차순
- 20건 단위 페이지 이동, 총 건수 표시
- 행을 누르면 상품 상세로 이동한다. ADMIN에게만 '상품 등록' 버튼을 표시한다.

### 3.2 상품 상세 · 사용 중지 — SCR-PROD-002

**관련 요구사항**: REQ-PROD-002, REQ-PROD-005 · **사용 역할**: 조회 A, M, U / 수정 · 사용 중지 A · **관련 규칙**: BR-023

- 표시: 상품코드, 상품명, 카테고리, 매입가, 판매가, 상태, 등록 일시, 수정 일시
- ADMIN 버튼: 수정, 사용 중지(상태가 '사용'일 때) / 다시 사용(상태가 '사용 중지'일 때)

| 작업 | 확인 대화상자 |
|---|---|
| 사용 중지 | 상품을 사용 중지하시겠습니까? 새 판매 · 발주에서 선택할 수 없게 됩니다. 남은 재고와 기존 이력은 유지됩니다. |
| 다시 사용 | 상품을 다시 사용하시겠습니까? |

- 사용 중지해도 재고 수량은 그대로 남으며, 재고 조정으로 정리할 수 있다.
- 이미 등록된 발주(작성 · 승인)는 그대로 진행할 수 있다. ([발주 명세 1.3](03-spec-purchase.md#13-사용-여부-확인-시점))

### 3.3 상품 등록 · 수정 — SCR-PROD-003

**관련 요구사항**: REQ-PROD-003, REQ-PROD-004 · **사용 역할**: A · **관련 규칙**: BR-020~022, BR-041

#### 입력 항목

| 항목 | 필수 | 형식 · 범위 | 설명 |
|---|---|---|---|
| 상품코드 | 필수 | 영문 대문자 · 숫자 · 하이픈(-), 1 ~ 20자 | 중복 불가. **등록 시에만 입력**, 수정할 수 없다. |
| 상품명 | 필수 | 1 ~ 100자 | |
| 카테고리 | 필수 | 등록된 카테고리 | |
| 매입가 | 필수 | 정수 0 ~ 99,999,999 | 발주 단가의 기본값 |
| 판매가 | 필수 | 정수 0 ~ 99,999,999 | 전 매장 공통 |

- 판매가가 매입가보다 낮으면 저장 전에 `판매가가 매입가보다 낮습니다. 저장하시겠습니까?`를 확인한다. (막지는 않음)
- 판매가를 바꿔도 이미 완료된 판매 금액은 바뀌지 않는다. (BR-041)

#### 서버 처리 — 상품 등록

```
[검증]
V1. 역할이 ADMIN인지 확인
V2. 입력 형식 · 범위 확인, 카테고리 존재 확인
V3. 상품코드 중복 확인

[트랜잭션 시작]
1. 매장 · 상품 등록 공통 잠금을 획득한다 (4장 참고)
2. 상품을 저장한다 (상태 '사용')
3. 모든 매장(사용 중지 매장 포함)에 대해 이 상품의 재고 행을 생성한다
   (수량 0, 안전재고 0 — 판매 · 재고 명세 1.5)
[트랜잭션 종료]
```

#### 서버 처리 — 상품 수정

- 상품명, 카테고리, 매입가, 판매가를 변경하고 수정 일시를 기록한다. 상품코드는 요청에 있어도 무시한다.

#### 오류 메시지

| 상황 | 메시지 |
|---|---|
| 필수 항목 누락 | {항목명}을(를) 입력하세요. |
| 상품코드 형식 오류 | 상품코드는 영문 대문자, 숫자, 하이픈(-)으로 20자 이하로 입력하세요. |
| 상품코드 중복 | 이미 사용 중인 상품코드입니다. |
| 가격 범위를 벗어남 | 가격은 0 이상 99,999,999 이하로 입력하세요. |
| 없는 카테고리 | 존재하지 않는 카테고리입니다. |

## 4. 매장 · 상품 등록 공통 잠금

상품 등록과 매장 등록이 **동시에** 실행되면, 서로 상대가 아직 커밋하지 않은 데이터를 보지 못해 그 매장 × 상품 조합의 재고 행이 빠질 수 있다.

```
관리자 A: 상품 P 등록 → (매장 S가 아직 안 보임) → P의 재고 행을 기존 매장에만 생성
관리자 B: 매장 S 등록 → (상품 P가 아직 안 보임) → S의 재고 행을 기존 상품에만 생성
결과: (S, P) 재고 행 없음
```

- 이를 막기 위해 상품 등록과 매장 등록은 **같은 잠금 하나를 먼저 획득한 뒤** 처리한다. (PostgreSQL advisory lock)
- 두 작업 모두 ADMIN만 하는 드문 작업이라 대기로 인한 영향은 거의 없다.
- 매장 등록 쪽 처리는 [시스템 관리 명세](03-spec-system.md)에서 같은 잠금을 사용한다.

| 사업자등록번호 | 필수 | 숫자 10자리 (하이픈 입력 허용) | 중복 불가. 화면에는 `000-00-00000` 형식으로 표시 |
| 담당자명 | 선택 | 0 ~ 50자 | |
| 연락처 | 선택 | 숫자 · 하이픈, 최대 20자 | |

- 수정 팝업에는 사용 중지 / 다시 사용 버튼을 표시한다.
- 사용 중지된 공급처는 새 발주에서 선택할 수 없고, 진행 중인 발주(작성 · 승인)는 그대로 처리할 수 있다.

| 상황 | 메시지 |
|---|---|
| 필수 항목 누락 | {항목명}을(를) 입력하세요. |
| 사업자등록번호 형식 오류 | 사업자등록번호는 숫자 10자리로 입력하세요. |
| 사업자등록번호 중복 | 이미 등록된 사업자등록번호입니다. |
| 연락처 형식 오류 | 연락처는 숫자와 하이픈(-)으로 20자 이하로 입력하세요. |
